# Contributing

- One issue and one focused behavior change per PR.
- Add tests before changing security, payment, persistence, or public API behavior.
- Include toolchain versions and exact reproduction commands.
- Discuss Candid and stable-data compatibility.
- Do not commit identities, seeds, API keys, customer data, or private prompts.
- Use English for source-code comments and public API names.
- Update documentation and threat model with behavior changes.

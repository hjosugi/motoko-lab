# Design — 06 Distributed LLM

## 何を測るためのアプリか

「LLM を分散させると速くなるのか」は、そのままでは答えられない問いです。分散の
コストは 2 種類あり、どちらが効くかは配置で決まります。

1. **逐次ラウンド数** — モデルを何回、順番に呼ぶか。分散配置では往復回数。
2. **転送バイト数** — ノード間に何を流すか。

このアプリはこの 2 つを、6 つの戦略について同一条件で数えます。速度は測りません。
インタープリタとレプリカでは実行速度が違いますし、語彙 336 の n-gram の実時間には
意味がないからです。数えたカウンターを実時間に変換するのは `tools/latency-model.mjs`
の役目で、そちらはネットワーク条件を明示的なパラメータとして受け取ります。

## モデルの選択

order-3 バックオフ n-gram、語彙 336、スコアはすべて `Nat` です。

Transformer ではないのは意図的です。必要な性質は 3 つだけでした。

* **決定的であること。** サブネットの全レプリカがビット単位で一致しなければなりません。
  浮動小数点はこれを壊す典型例なので、確率 `c / n` は `SCALE * c / n` の固定小数点で
  持ちます。
* **2 段階の能力差があること。** `order = 3` を TARGET、`order = 2` を DRAFT とします。
  安価なヘッドが高価なヘッドと同じトークナイザを共有し、しかし出力は一致しない —
  これが投機的復号が成立する条件そのものです。実測で 200 位置中の一定割合が不一致に
  なることを `test/Lm.test.mo` が確認しています (全一致でも全不一致でもないこと)。
* **文脈が欠けても壊れないこと。** 拡散的ドラフトはマスクされた位置から始まります。
  文脈を `?TokenId` で持ち、`null` は短い n-gram へのバックオフとして扱います。これで
  「左隣がまだ埋まっていない位置」を特別扱いせずに書けます。

## 検証規則

3 つの復号器が共有する規則は 1 つです。

```
t_i = argmax_TARGET(prompt ++ draft[0..i-1])
最初に draft[i] != t_i となる i まで採用し、t_i を出力して残りは捨てる
全一致なら draft 全部 + t_block を出力する
```

`t_i` は prompt と確定済みドラフトだけに依存するので、`block + 1` 個すべてが独立で、
1 回のバッチパス = 1 往復に収まります。これが投機的復号の要です。

出力が構成上ターゲットの貪欲継続に一致することは証明できますが、実装がそれを守って
いるかは別問題なので、`Speculative.identical` で毎回照合し、`Report.lossless` として
報告します。`test/Speculative.test.mo` は 9 プロンプト × block {1,2,3,4,8,16} ×
steps {1,2,3,4} を総当たりします。

## 拡散的ドラフトの実装

`maskedDraftBlock` は `block` 個のスロットをマスク状態から始め、各ステップで

1. マスク中の全スロットを現在の部分列から採点する (相互に独立 = 1 ラウンド)
2. 信頼度上位 `ceil(remaining / stepsLeft)` 個をアンマスクする

を繰り返します。信頼度は `top / sum` を `SCALE` 倍した整数で、同値はスロット番号で
割ります。スケジュールが再現可能でなければレプリカ間で結果が変わるためです。

`steps < block` なので、ドラフト段の逐次パスは `block` 回ではなく `steps` 回で済みます。
代償は 1 パスあたりの演算量で、`draftEvals` が増えます。これは論文が主張する
トレードオフそのもので、実測でも受理率が 33% → 20% に落ちています。左から右への
条件付けを捨てた分だけドラフトの質が落ちる、と読むのが正しい解釈です。

## シャーディングとワイヤ形式

語彙を連続区間に分割し、各ワーカーが自分の区間だけを採点します。返し方は 3 つ。

| 形式 | バイト数 (語彙 336, 4 シャード, 24 トークン) | 厳密か |
|---|---|---|
| `#argmax` | 640 | はい |
| `#quantized 8bit floor` | 4,000 | はい (下記) |
| `#dense` | 27,200 | はい |

マージ規則は全形式で共通で、同点は最小トークン ID を採ります。この規則がないと
シャード構成と単一ノードが別の答えを返し得るので、シャーディングが「実装の詳細」で
なくなってしまいます。`test/Sharding.test.mo` がシャード数 {1,2,3,4,7} × 形式 4 種 ×
コーパス 118 位置で単一ノードとの一致を確認します。

## 量子化がいつ損失になるか

**リダクション上では無料です。** 切り捨て絶対値最大量子化 `code = v * L / max` は
単調非減少で、`code = L` は `v * L >= L * max`、すなわち `v = max` のときにしか
起きません。最大値だけが最上位コードに到達し、しかも誤差は片側にしか出ないので、
現在の首位は順位を落とせません。argmax は任意のビット幅で保存されます。

**アキュムレーション上では損失があります。** パイプラインでは受信側が順位ではなく
値を必要とします。各ホップで再量子化すると誤差が積み上がり、後段のステージが厳密
演算なら区別できたはずのトークンを区別できなくなります。

そして**この保証を担っているのは切り捨てです**。最近傍丸めにすると誤差が両側になり、
実測で 8 ビット 19/398、2 ビット 43/398 の位置でトークンが変わります。「低ビットでも
壊れなかった」という観測は、丸めモードを書かずに引用すると誤りになります。

さらに、損失があっても**厳密な検証器の後段に置けば出力は変わりません**。変わるのは
受理率だけです。量子化と投機的復号が噛み合うのはこの構造のためです。

## パイプラインのステージ重みについて

`Pipeline.Profile` に `#natural` と `#balanced` があります。

`#natural` はこのモデル自身の重み (trigram 1000 : bigram 60 : unigram 1) です。
ステージ 1 が単独で勝者を決めるため、下流で何ビットに落としても結果は変わりません。
これは量子化が安全だという証拠ではなく、**このモデルの階層構造がそうなっている**と
いうだけです。

`#balanced` は各ステージを同じ大きさに正規化します。Transformer の残差ストリームは
層ごとの寄与が同程度なので、そちらに近い状況を作るためのものです。`#balanced` は
モデルを変えてしまうので、比較対象は「同じ profile をフル幅で走らせた結果」であって
単一ノードの出力ではありません。`sim/Cluster.mo` の表は `=exact` 列と `=single` 列を
分けてそれを明示します。

対照条件を用意せずに「量子化しても壊れなかった」と書くのは、測っていないことを
測ったことにする類の誤りなので、両方を残しています。

## ICP 固有の制約

* `query` は inter-canister call を作れません。したがってファンアウトする
  `generate` は update call であり、合意を通ります。ワーカー側は `query` なので、
  クライアントは合意を介さず直接ワーカーを読めます。update から query メソッドを
  呼ぶことはでき、レプリカは replicated モードで実行します。
* シャーディングはキャニスターあたりのメモリを割りますが、サブネットの複製係数は
  割りません。33 ノードのサブネットでは、シャードを増やしても総計算量は減りません。
  減るのは 1 キャニスターが抱えるメモリだけです。
* 1 メッセージあたりの命令数上限があるので、`maxTokens` は上限付きです。
  `Validation.tokenBudget` は拒否せずクランプします。過大な要求には短い答えを返す方
  が、エラーを返すより実際の制約に近い挙動です。
* このデモのワーカーは全モデルを持ち、自分の範囲だけを評価します。本番のシャードは
  パラメータも分割します。ここで示しているのは通信パターンであって、メモリ削減では
  ありません。

## 測っていないこと

* 生成品質。語彙 336 の n-gram です。
* サイクル消費。カウンターは命令数ではなくラウンドとバイトです。
* アップグレード時の状態移行。モデルは `transient` で毎回再構築します。
* メインネットの実レイテンシ。`tools/latency-model.mjs` は推定であって計測では
  ありません。
* 実 LLM の受理率。ここでの 33% は n-gram の draft/target 対の値で、Llama 級の
  モデルとは関係ありません。
